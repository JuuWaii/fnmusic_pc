# 原生歌曲搜索：实现与验收

更新：2026-09-15。

## 实现

- 搜索按钮及 Enter 提交，清空或空白关键词恢复曲库第一页；翻页、刷新使用已提交的关键词。
- GET `search/track?q=…&page=…&size=…`，关键词 Trim 后按查询参数编码，长度上限 256。复用曲库曲目解析、鉴权及响应大小限制。
- 曲库/搜索请求使用独立取消源。新搜索撤销旧请求，旧响应不能写回列表；切歌不会取消搜索。会话变更及关闭窗口撤销请求。
- 每次搜索开始清除旧列表并禁用分页；错误提示可重试，空结果有明确提示。搜索及清空不改变已经建立的播放队列。
- 从搜索结果播放时固定当前页快照，并显示搜索队列来源。

## 接口证据与验证

缓存的已审查 NAS 前端调用为 `search.track({q: query, page, size})`，消费 `list` 与 `total`，歌曲继续使用同一映射。2026-09-15 已完成当前实例只读验证；服务端忽略 page/size 并返回完整集合，原生兼容见下文。

28 项原生检查通过，搜索测试覆盖中文和保留字符编码、分页参数、时长映射、非法输入不发送 HTTP、空结果、401 和畸形响应。Debug/Release 编译均为 0 警告、0 错误。

合成窗口已实测：输入 b 后点击搜索，列表只剩 B；播放结果显示搜索队列 1/1；清空后恢复 A/B 曲库，B 保持播放且队列仍为 1/1。

回车绑定改为通过 AddHandler 接收处理过的路由键盘事件后，2026-09-15 合成窗口复测通过：数字关键词可直接回车提交；输入处于组合状态时，确认输入后再次回车提交成功。更广泛输入法兼容性仍待回归。

专用 Debug 参数 `--preview-synthetic --preview-search` 提供 122 首合成曲目，不读取会话、不访问 NAS；与正常窗口共用 XAML、事件及请求写回检查。已完成以下窗口验收：

- 搜索 `0` 命中 111 首，第二页从 051 开始、第三页从 101 开始，末页禁用下一页；上一页返回第二页。
- 搜索 `z` 显示无匹配提示，两个分页按钮均禁用；清空恢复曲库第一页 122 首。
- 搜索 `slow` 模拟不响应取消的 20 秒旧请求，加载期间列表清空、分页禁用；约 9 秒时清空搜索，约 29 秒时复查仍为曲库 122 首且首行 A/B，迟到结果没有覆盖新列表。

以上为合成窗口验收；真实 NAS 连续快速查询、网络超时和更多输入法组合仍保留为扩展回归。

## 真实 NAS 验证与分页兼容

`--verify-native-search` 为仅 Debug 启用的显式只读检查：使用本应用加密会话，读取一首曲目，在内存使用其标题搜索，核对分页及无结果查询。报告只含时间、固定检查项、阶段及异常类型，输出到对应 Debug bin 的 `search-verification.json`，不输出关键词、曲名、地址或会话。

此前执行因缺少明确授权被自动审批拒绝；用户确认继续后，本轮已获准并完成同范围只读验证。检查进程已退出，报告时间晚于测试开始，最终 stage=complete，所有检查项通过。

实测发现：精确标题命中成功；短前缀产生多个结果时，page=1/2、size=1 均返回同一完整集合，条数等于 total。初版把这当作服务端分页，导致翻页重复。当前只在返回条数等于 total 时按请求页在内存切片；真正的服务端分页保持原样。超长且不完整或条数超过 total 的响应拒绝处理，保留 2 MiB 响应上限，不静默截断。

真实回归已证明：多个匹配结果下首/次页各一首、两页不同且总数一致，无匹配返回空集。测试未写歌单、收藏或 NAS 配置。新增回归覆盖完整集合、末页、超范围页、极大页码、正常服务端分页及畸形集合。

真实接口检查使用独立 `.review-audit/search-build/` 输出，最终脱敏报告位于该目录。后续窗口验收使用 `.review-audit/search-ui-build/`，Debug 和 Release 均成功构建，0 警告、0 错误。
