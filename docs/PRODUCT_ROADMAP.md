# 产品需求与实施优先级

更新：2026-09-22。此文是当前需求排序的主记录，替代此前“新增需求统一低优先级”的安排。开发完成和验证状态见 [开发清单](NATIVE_BACKLOG.md)；阶段历史不代表当前全部能力。

## 产品目标

Windows 原生多音乐源客户端：保留飞牛音乐服务端能力，统一浏览和播放本地及第三方音乐源，支持跨库本地歌单、飞牛同步歌单、封面与歌词、系统主题及对外播放信息。

## 排序原则

先完成已有功能的可靠性闭环，再建立多源基础，随后接入依赖它的歌单和服务。小而独立的主题能力可提前完成。界面整体重设计和桌面歌词放在核心数据与播放链路稳定之后。每个节点均包含相应测试和实际操作验收，不把“已写代码”当作“已完成”。

| 顺序 | 优先级 | 工作项 | 原因与完成边界 |
| --- | --- | --- | --- |
| 1 | P0 | 收藏功能收尾与基础可靠性 | 完成合成增删、失败恢复、真实只读及适当范围写入验收；继续保护会话、队列与取消行为 |
| 2 | P0 | 多音乐源与音乐库基础模型 | 明确源实例、账户、库、曲目身份和能力；避免不同服务相同 ID 冲突，是跨库歌单基础 |
| 3 | P1 | 本地音乐与音乐库分类 | 目录导入、扫描、元数据、播放、增量更新和失效文件；支持库命名、分组、筛选及来源标识 |
| 4 | P1 | 跨音乐库本地歌单 | 可混合多个已接入库的歌曲、排序和保存；离线源不导致歌曲条目被删除 |
| 5 | P1 | 飞牛专属同步歌单 | 与本地歌单同级显示；创建、改名、增删歌曲和排序按真实 API 能力实施，同步网页端数据 |
| 6 | P1 | 飞牛非 UI 设置与素材库同步 | 先核对接口、作用范围和权限，再分批接入素材库、用户设置、支持的服务端设置 |
| 7 | P1 | 浅色、深色、跟随系统 | 默认跟随 Windows；系统变化实时生效，手动选择可持久保存；不修改 Windows 设置 |
| 8 | P2 | 第三方音乐源 | 建议先 Navidrome，再 Emby，最后自定义通用音乐源；逐个完成认证、库、搜索、分页和播放验收 |
| 9 | P2 | 封面与应用内歌词 | 歌曲/专辑封面加载与缓存，歌词获取、时间轴、滚动和跳转同步，无内容与失败状态明确 |
| 10 | P2 | 对外音乐与歌词信息 | 先 Windows 系统媒体信息与控制，再可发现的本地只读元数据/歌词接口；各软件兼容性分别验证 |
| 11 | P2 | 播放、连接与桌面能力扩展 | 大文件随机读取、更多格式、CUE/HLS、FN Connect/OAuth、断线恢复、设备热插拔、托盘、快捷键和睡眠定时 |
| 12 | P3 | 整体 UI 优化 | 参考 Apple Music、网易云音乐、飞牛音乐；设计阶段调研开源音乐客户端，形成统一导航、播放器及详情布局 |
| 13 | P3 | 桌面歌词 | 基于稳定的歌词时间轴实现独立歌词窗口，支持开关、位置和显示偏好 |
| 14 | 发布关卡 | 分发与安装升级 | 固定 FFmpeg 分发版本及许可/源码材料，完成隐私、打包内容、安装升级及完整回归；用户已取消本次测试版打包 |

优先级表示默认工作顺序，不要求串行等待所有 P1 才开始某个独立小功能。主题可作为短节点提前实现；媒体键与系统媒体信息应一起设计。后续发现协议限制时更新完成边界，不虚构第三方能力。

## 关键功能定义

### 音乐源、音乐库与身份

- 音乐源是一个连接实例，例如某个飞牛账户、Navidrome 服务、Emby 服务或本地目录集合；同一服务类型可有多个实例。
- 音乐库属于音乐源。分类/分组是本机组织方式，默认不改变服务端目录或分类。
- 曲目身份至少包含源实例与源内 ID；库归属另外保存。跨源同名歌曲不自动合并，本地文件移动需要重关联机制。
- Provider 能力应区分只读浏览、播放、收藏、歌单写入、设置写入、歌词与封面；不支持的操作明确显示，不能默默降级为另一种写入。
- 各源独立保存凭据、分页和请求生命周期。某个源离线不阻塞其他源，删除连接不应静默删除本地歌单中的引用。

### 两类同级歌单

1. **本地歌单**：保存在电脑，可引用任意已接入音乐库；不自动同步到某个远端。断网、源失效或曲目缺失时保留条目并显示可用性。
2. **飞牛歌单**：绑定具体飞牛源/账户，以服务端记录为准；在软件内新建或编辑后同步至飞牛，网页修改也可刷新到软件。

用户此前要求的“本地创建并同步飞牛”对应在客户端创建飞牛歌单；本地跨库歌单仍单独存在。以后若支持导出/转换，只有能明确映射至目标飞牛曲库的歌曲才可同步，无法映射时逐项说明，不能仅按歌名匹配或悄悄丢弃。

飞牛歌单需要记录远端 ID、同步状态、失败和冲突。首版以显式保存及刷新为主，不承诺实时推送；若接口支持版本信息再使用版本校验，否则重新读取比较，不能覆盖网页端的新修改。

### 飞牛素材库与非 UI 设置

“素材库”先按飞牛网页中的库/素材目录管理理解，实施时核对实际页面与 API 名称。建立字段清单：读写接口、用户级或服务器级作用域、权限、是否需要后台扫描或重启。

先展示真实设置，接着允许修改已验证可写项；保存后回读确认。网页端修改通过刷新/重新进入同步，后续再评估轮询或事件机制。客户端主题、窗口尺寸等 UI 偏好留在本地；密码、令牌等认证材料不作为普通设置同步。服务端不支持的能力不能用本机伪设置冒充成功。

### 第三方与通用音乐源

本地音乐先打通扫描和播放，再用已建立的 Provider 接口接入 Navidrome、Emby。协议、鉴权、分库方式和格式/转码需求均在接入时以官方资料与实际服务核验，不能直接沿用飞牛端点。

“自定义通用音乐源”首版规划为受控的 HTTP/JSON 配置适配：连接地址、认证方式、列表/详情/播放/封面/歌词映射与分页规则。它不是任意执行脚本，也不保证适配所有音乐平台；配置版本、响应限制和来源边界要可检查。

### 对外可发现的音乐及歌词信息

第一层接入 Windows 系统媒体传输控件（SMTC），提供曲名、歌手、专辑、封面、播放状态及可支持的播放控制/进度，供系统及兼容软件使用。

第二层设计可选、版本化的本机只读信息接口，公布发现方式、能力说明、当前播放源、曲目标识、时长/进度、状态变化和歌词时间轴。系统媒体接口不等于通用歌词协议，不能声称所有软件都会自动发现或显示歌词；应选定消费端逐一联调。接口不暴露凭据、服务器私有地址或本地完整文件路径，默认不对局域网开放。

## 保留的验收与限制

- 播放：真实大文件、连续快速拖动、键盘/触摸、超时恢复、格式矩阵与长时间播放。
- 浏览：更多输入法组合、快速连续查询/导航、真实网络断连、失效会话与不同窗口尺寸。
- 同步：重复提交、失败重试、网页并发修改、切换账户和离线后的重新核对。
- 现有飞牛登录、曲库、搜索、专辑/歌手、关联专辑和队列已有阶段性验收；收藏基础已接入，新增场景仍待收尾。多源已增加领域类型和队列来源身份隔离，账户级实例持久化及 Provider 路由仍待接入；设置同步、两类歌单与信息接口仍待开发。

## 最近三个开发节点

1. 完成收藏合成窗口回归与只读接口验证，形成可追踪的本地提交。
2. 实现源实例/音乐库/曲目引用的领域模型及能力边界，迁移现有飞牛单源调用，不改变当前播放行为。
3. 接入本地目录库与最小跨库歌单持久化，再推进飞牛同步歌单；主题切换作为独立短节点穿插完成。
